# Database schema

## Source of truth

The canonical schema is
[`backend/prisma/schema.prisma`](../backend/prisma/schema.prisma). Update that
file first and keep this document synchronized. PostgreSQL is the only
supported application database.

## Tables

Prisma maps the models below to lowercase plural table names.

| Column | Type / rule | Notes |
|---|---|---|
| `id` | UUID string, primary key | Generated by Prisma |
| `fullName` | String, required | |
| `email` | String, unique, required | Login identifier |
| `passwordHash` | String, required | bcrypt hash, never return from API |
| `phone` | String, nullable | |
| `role` | `Role`, default `CUSTOMER` | |
| `status` | String, default `active` | Current account status |

Relations: one optional provider profile; customer and provider bookings;
customer and provider reviews.

|---|---|---|

Relations: customer, provider, and booking. The current schema does not enforce

## Relationship overview

```text
User 1 ── 0..1 Profile 1 ── * Service 1 ── * Booking
User (customer) 1 ── * Booking
User (provider) 1 ── * Booking
Booking 1 ── * Review
User (customer) 1 ── * Review
User (provider) 1 ── * Review
```

## Not yet modeled

Messaging/conversations, working-hour schedules, notifications, reports,
moderation events, and categories are not separate persistent models yet.
Avoid assuming those concepts persist just because frontend demo screens exist.

## Database commands

Run from the project root:

```sh
npm run db:generate
npm run db:push
npm run db:studio
```

Use `db:push` for development. Use reviewed and committed Prisma migrations
for production schema changes.
